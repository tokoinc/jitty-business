## 分類の原則

主カテゴリは5個、初期タグは23個。カテゴリは読者が次の働き方を選び準備する道筋、タグは具体的なテーマを横断して探すための分類とする。記事は主カテゴリ1個、タグ2〜4個を基本とし、同じ本文を複数カテゴリの別URLで公開しない。

「50代」はサイト全体の対象なのでタグにしない。「独立」「転職」はカテゴリと重なるためタグにしない。記事形式、読者目的、読者の状況、執筆優先度、公開段階は別の管理項目にする。「体験談・アンケート」は記事形式と編集一覧で扱い、「退職金を守る」はTD-19を核にした編集テーマとして案内する。

## タグの運用

1. 記事の主題である場合だけ付ける。本文で1回触れただけのテーマは付けない。ハブでも扱う全テーマをタグに詰め込まない。
2. 企業・サービス名は商品・サービス情報として管理し、初期タグにしない。年号や毎年変わる期限もタグにしない。
3. タグのIDは英小文字・数字・ハイフンで固定する。表示名を変更してもIDを維持し、重複・統合時は旧URLから転送する。
4. 初期23個は定義として登録し、公開記事が0本のタグのリンクは隠す。1〜2本のタグ詳細は閲覧用に残しても検索索引対象にしない。
5. タグ詳細を検索対象にする目安は公開済み関連記事3本以上。記事数だけで自動公開せず、独自の説明・読む順番・カテゴリ横断の価値があるかを確認する。
6. 新規タグは今後も使う具体的なテーマで、3本以上の公開・企画記事への適用を見込める場合に追加する。初期の1本タグは既定の30記事に含まれるテーマとして例外的に定義し、検索ページの量産には使わない。
7. 早期退職・役職定年は、それぞれ固有の事情が主題の場合だけ付ける。全記事に一律付与しない。

## 実装時の項目

カテゴリは`id / label / description / order / shelf / tabSlot / reviewProfile / owner / updatePolicy`を持つ。5カテゴリのorder・tabSlotはA〜Eの順に1〜5、shelfはtrue。ownerは実際の編集者IDを設定する。

タグは`id / label / reading`を表示用に持ち、グループ・付与条件・別名は編集用の定義として管理する。読みは別添管理表に記載。D/Eはカテゴリ全体をsensitiveとし、A/B/Cでも制度・契約・金融の個別記事はsensitiveにする。確認担当は専門家監修とは表記しない。

記事の形式は`guide / tutorial / comparison / interview`など、目的は`learn / compare / choose / do / solve`として分類と分ける。TD-05は調査結果を整理するguide、人物単位の取材を追加したときにinterviewを使う。

この定義は既存テンプレートへの自動反映・置換を行っていない。タグページの検索対象制御や追加の編集一覧は採用するCMS側で実装する。
