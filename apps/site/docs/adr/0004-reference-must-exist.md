# 存在しない参照は sync を止める

## 状況

手順書 3.5 は、`reference()` が参照先の存在を検査し、存在しない棚 ID ではどのファイルのどの項目かが分かるエラーで止まると書いている。入っている Astro 7.3.5 では、この検査はコンテンツ同期のあとでログになるだけである。`node_modules/astro/dist/content/content-layer.js` には「Zod 4 への移行で、インラインの Zod 検査を外し、存在しない参照はログする」とある。`npx astro sync` と `npm run check` は、そのログを出しても終了コード 0 で終わる。

日付の引用符忘れと `format: review` は、従来どおり `InvalidContentEntryDataError` で止まる。

## 選択肢

1. ログのままにする。終了コードは 0 なので、存在しない棚 ID ではコマンドが止まらない。
2. `reference()` の直後に、ファイル上の ID があるかを見る検査を足し、無いときはスキーマエラーにする。

## 決定

選択肢2。`src/content.config.ts` の `ref()` が、YAML の `id`、著者・用語のファイル名、記事ディレクトリ名を読み、無い ID は `ctx.addIssue` する。フィールドの定義は手順書のスキーマのままである。

## 理由

工程4の確認は、存在しない棚 ID でコマンドが止まることである。ログだけでは、その確認を満たせない。ID の一覧はコレクションの読み込み順に依存させず、ファイルから取る。公開状態・自己参照・編集要件の検査は、手順書どおり工程5の `src/utils/validate.ts` に残す。
