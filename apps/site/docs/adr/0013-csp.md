# CSP は Astro の security.csp でハッシュを出し、style 属性だけ別にする

## 状況

工程21の手順6は、明暗の初期化のインラインスクリプトがあるため、採用版の Astro に CSP の機能があればそれを使い、無ければそのスクリプトのハッシュを `script-src` に入れる、と指定している。

採用版は Astro 7.3（`security.csp` は 6.0 からある）。build は各ページの `<head>` に `<meta http-equiv="content-security-policy">` を出し、そのページのスクリプトと `<style>` のハッシュを入れる。`dev` では効かない。

全ページに `style="--slot:…"` などの属性がある。これは手順書の部品（棚の位置、比較の列数、見出しの段）で、値はページごとに変わる。`<style>` のハッシュでは属性は許可されない。Pagefind は同じオリジンの WASM をコンパイルする。`frame-ancestors` は meta の CSP では無視される。

## 選択肢

1. ハッシュを手で計算し、`public/_headers` の `script-src` にだけ書く。`<style>` の中身はページで違うので、ヘッダー1枚には載らない。
2. Astro の `security.csp` を使う。スクリプトと `<style>` はハッシュ、`style` 属性は `style-src-attr 'unsafe-inline'`、WASM は `'wasm-unsafe-eval'`。`frame-ancestors` だけヘッダーに置く。
3. `style` 属性をクラスへ置き換え、`style-src-attr 'none'` にする。

## 決定

選択肢2。

- `astro.config.ts` の `security.csp`。`script-src` は `'self'` と `'wasm-unsafe-eval'` に、そのページのハッシュを足す。`style-src` は `'self'` と `<style>` のハッシュ。`style-src-attr` は `'unsafe-inline'`。`default-src 'self'`、`base-uri 'self'`、`object-src 'none'`。`img-src` は `'self'` と `data:`。モダンリアルの紙の粒（`--m-grain`）が SVG の data URL だからである。画像としての SVG はスクリプトを実行しない。
- `public/_headers` の CSP は `frame-ancestors 'none'` だけ。meta とヘッダーは両方適用される。ヘッダーに `script-src` を書くと、ページごとのハッシュが無く、インラインスクリプトが止まる。
- 実行される inline script は明暗の初期化の1つのまま（`check-output`、ADR-0012）。Astro は 4KB 未満のスクリプトを HTML に埋め込む。識別検査のスクリプトはそれより小さいので、`DD_INSPECT=1` の比較デモでは2つ目の inline script になり、検査が止まる。`vite.build.assetsInlineLimit` で `.js` だけ埋め込みを止め、外部ファイル（`script-src 'self'`）のままにする。CSS と画像の埋め込み判定は既定のまま。

## 理由

機能がある版なので、手順書どおり Astro の CSP を使う。属性の値は棚の数や記事の列数から出るので、事前に全ハッシュを列挙できない。クラスへ移すと3セットの部品と識別検査の形が変わる。属性だけを `'unsafe-inline'` にすれば、`<style>` とスクリプトはハッシュのまま残る。`'unsafe-inline'` を `style-src` 自体に置くと、同じディレクティブのハッシュが無効になる（CSP の規則。Astro もハッシュを出さなくなる）。

build は、`style-src` の `'self'` が `style-src-attr` には効かない、と警告する。属性は外部のスタイルシートを読まないので、`'self'` を属性側へは足さない。Shiki の警告は、本文にコードブロックが無いので、いまの画面には出ていない。
