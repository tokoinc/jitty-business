# 確かめる領域（付箋）は、確かめる情報があるページだけに出す

## 状況

工程8b では、全ページを3列にそろえるため、手順書 2.3 の表にない画面（404・運営情報・保存一覧・著者）にも `CheckPanel` を置いていた。その中身は、404 の「ほかの入口」（`kind="toc"`）、運営4ページの相互リンク（`kind="toc"`。別ページに `aria-current="location"`）、保存一覧の説明（`kind="selected"`）、本文の繰り返し（用語ページの「この用語」、用語集の0件、著者の「この著者」。いずれも `kind="shelf"`）だった。

手順書は次のように定めている。

- 2.6 の部品表：付箋は、確かめる領域の部品（目次・条件・根拠・選択中の条件・読みかけ・連載・最近確認した記事）と、本文の条件欄・根拠欄だけに使う。
- 0.2-7：形の予約（2.1 P2）に反する部品の流用をしない。
- 1.3：シグネチャ部品を見せるために空の枠を作らない。
- 3.7：`aria-current="location"` は目次の節に使う。

用語ページでは、2.3 が確かめる領域に「使われている記事、関連用語」を求めている。3.7 の `CheckPanel` の kind には、使われている記事に当たるものがない。

## 選択肢

1. 全ページで3列にそろえ、確かめる情報がないページは、ほかの kind を借りて埋める。
2. 確かめる情報があるページだけ付箋を出す。ないページは2列にする。用語ページは、本文側の節への目次（`kind="toc"`）で「使われている記事」へ入れるようにする。
3. `CheckPanel` の kind に、使われている記事などを足す（3.7 の契約を変える）。

## 決定

選択肢2。

- 404・運営4ページ・保存一覧は付箋を出さない。404 の入口（棚の一覧・記事一覧・目的・用語集）は読む領域に置く。運営情報への入口はフッターにある。
- 用語ページは「目次」（関連する用語・使われている記事・出典の節へ。件数付き）と「関連する用語」（あるときだけ）にする。
- 用語集・著者は、用語がないときは付箋を出さない。
- `kind` は、3.7 と 2.6 の意味（toc＝そのページの節の目次、shelf＝棚の説明・確認担当・更新方針、terms＝関連する用語、selected＝選択中の条件、ほか）のとおりに使う。

## 理由

付箋の形は、確かめる情報に予約されている。穴埋めに使うと、P2 に反し、セットの識別も弱くなる。Board では、toc の項目はキーの形になり、selected は条件の解除になる。そのため、kind を流用すると、セットを替えたときに意味の違う形で描かれる。

Frame は check スロットが空なら aside を出さない（工程8a）。parts.css の `.bi-frame:not(:has(.bi-flags))` で2列になる。記事が0件の目的のページは、すでにこの形である。

契約を変えずに 2.3 を満たせるのは、目次で本文側の節へ入れる方法である（2.3「確かめる領域は本文の該当箇所への入口と要約」）。
